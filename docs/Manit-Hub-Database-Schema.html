Overview — All Collections

Conventions used throughout: every collection has an implicit _id (ObjectId) primary key and createdAt/updatedAt timestamps (timestamps: true). Almost every collection carries a required, indexed university → University reference — the app is multi-tenant and every query is scoped to the user's university. * marks required fields. ObjectId→X means a reference to collection X.

7 · Relationship Map

University is the tenant root — referenced (required + indexed) by every collection except Notification.

User is referenced by: Listing.seller, Offer.buyer/seller, Conversation.participants, Message.sender, Document.uploader/upvotes/comments.author, Question.author/upvotes, Answer.author/upvotes, StudyGroup.creator/members, AcademicRecord.user, AttendanceSubject.user, TimetableEntry.user, Confession.author/reactions/comments/reports, Event.organizer/attendees, LostFoundItem.reporter, Ride.poster/passengers, Friendship.requester/recipient/users, Notification.user, DeviceToken.user, Report.reporter/handledBy, and User.savedListings → Listing.

Polymorphic links: Conversation.listingId points at a Listing, LostFoundItem or Ride depending on contextType; Notification.relatedId uses refPath (Listing/StudyGroup/Message/User/Conversation); Report.targetId is typed by targetType (8 content types).

Denormalized counters (kept in sync by controllers): Question.upvoteCount/answersCount, Answer.upvoteCount, Document.upvoteCount/downloadCount, Confession.reactionsCount, Conversation.lastMessage/lastMessageAt, Offer.seller.
